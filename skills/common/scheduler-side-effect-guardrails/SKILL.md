# 排程副作用守門規則

排程與可重試工作必須能安全面對延遲執行、重複執行、部分完成或部署後再執行。

## 作業流程

1. 定義時間語意：時區、精確截止時間、含邊界/不含邊界比較，以及目前時間來源。
2. 分離狀態轉換、通知、外部呼叫與稽核日誌，確保每個副作用都有明確意圖。
3. 讓操作具備冪等性，或以持久狀態保護條件保護。
4. 決定併發執行如何鎖定或去重。
5. 定義重試、逾時、退避與部分失敗行為。
6. 使用固定時鐘加入邊界前、邊界當下、邊界後的測試。
7. 記錄維運驗證方式：指令名稱、排程註冊、日誌、指標，以及回復或向前修復路徑。

## 檢查清單

- 重新執行工作不會重複通知、付款、匯出或不可逆外部呼叫。
- 部分失敗可重試，且不會破壞狀態。
- 長時間工作有分塊、佇列、鎖定或邊界限制。
- 工作不依賴僅控制器驗證或僅請求脈絡。
- 排程狀態變更後，面向使用者的 API 行為仍保持一致。

## 停止條件

遇到以下情況，編碼前應停止：

- 截止時間或時區未指定。
- 操作有不可逆外部副作用，但沒有冪等鍵或人工復原計畫。
- 正式環境可能已有資料會受排程規則變更影響。
- 工作會改變授權、計費或生命週期狀態，但沒有可測試的狀態轉換契約。
