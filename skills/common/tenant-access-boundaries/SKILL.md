# 租戶存取邊界

租戶邊界是資料安全邊界。應將租戶脈絡視為授權的一部分，而不是表面的過濾條件。

## 作業流程

1. 找出權威租戶脈絡：權杖、工作階段、成員資格、路由綁定、服務脈絡或工作載荷。
2. 找出所有使用者提供的租戶識別值，並決定要信任、忽略、交叉檢查或拒絕。
3. 沿著租戶邊界追蹤讀取、寫入、匯出、通知與背景工作。
4. 將租戶範圍限制放在共享查詢範圍、政策、中介層或服務，而不是散落在控制器條件判斷。
5. 分別驗證列表 API、詳情 API、變更操作、檔案存取與匯出。
6. 支援時加入同租戶成功、跨租戶拒絕、缺少租戶脈絡、停用成員資格與特權覆寫路徑測試。

## 檢查清單

- 使用者不能透過修改請求載荷或查詢字串選擇其他租戶。
- 列表端點依 API 契約，對跨租戶存取回傳空結果或拒絕。
- 詳情、更新、刪除、匯出與檔案下載路徑執行與列表相同的邊界。
- 背景工作攜帶足夠租戶脈絡，避免跨租戶副作用。
- 管理員或支援覆寫必須明確、可稽核，且有測試。
- 回應與日誌不洩漏其他租戶識別值或敏感欄位。

## 停止條件

遇到以下情況，實作前應停止：

- 權威租戶來源不清楚。
- 產品規則對擁有者、成員、管理員或支援覆寫行為互相衝突。
- 資料庫遷移或資料回填可能在沒有資料計畫的情況下重新指派租戶歸屬。
- 既有測試暗示的租戶邊界與最新需求不同。
