# Claude 5 世代指令撰寫

Claude 5 世代模型能理解原則並自行評估例外，過度約束反而讓模型耗費推理處理互相衝突的指令。撰寫給 agent 讀的指令時，目標是給足判斷依據，而不是窮舉情境。

## 適用範圍

適用於 Claude 5 世代（Opus 5、Fable 5 等）具判斷能力的模型。舊世代模型缺少這些護欄，直接放寬約束等同拆掉防翻車措施。安全、金流、破壞性操作與合規等高風險領域仍保留嚴格約束。

## 四條原則

- **立原則，不立死規矩。** 描述目標狀態而非禁令。規則若存在合理例外，就把判斷權交回模型：「跟隨周圍程式碼的註解密度與命名慣例」勝過「絕不寫多段註解」。
- **介面設計優先於範例堆疊。** 讓工具參數名稱、選項與欄位本身就能說明用法；大量範例會把模型鎖在單一路徑。範例保留給輸出格式、特殊案例與難以言傳的品味。
- **漸進揭露。** 主要指令檔只留常駐規則與指路，其餘放 `references/` 或獨立 skill 供按需載入。凡是 agent 自己讀專案就能發現的事，一律刪除。
- **用高保真參照物取代文字描述。** 測試碼、既有實作、原型或評分準則比一段規格敘述精確，也讓模型能自我驗證。

## 作業流程

1. 逐條問「agent 自己翻專案會不會發現」，會則刪除；框架與語言本身的通用最佳實務同樣刪除，只留專案獨有的觀點與陷阱。
2. 逐條問「有沒有合理例外」，有則改寫成原則加判斷依據。
3. 檢查「絕不」「一律」「必須」「禁止」等絕對措辭，只保留高風險且真正無例外者。
4. 同一件事重複強調的段落合併為一處。
5. 主文件超出常駐所需長度時拆進 `references/`，正文只留一行指路；`CLAUDE.md` 以 200 行內為目標。
6. 能指向測試、既有實作或評分準則的段落，改為指路而非複述。

## 停止條件

- 目標 agent 不是 Claude 5 世代模型。
- 要放寬的是權限、金流、資料刪除、對外發布等高風險約束。
- consuming project 的執行期約束與本原則衝突；此時專案規則優先，不回灌共享指令。

## 驗證

精簡後以一項真實任務實際跑過，確認行為未劣化才算成立。未驗證即交付時，說明原因與未涵蓋風險。
